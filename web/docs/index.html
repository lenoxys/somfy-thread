Serial console

The firmware exposes a line-oriented console over the ESP32-C6 native USB (USB Serial/JTAG), 115200 baud, 8N1. The setup wizard on the home page drives it through WebSerial — everything below is the same command surface, so you can also type these into any serial terminal (screen, picocom, PlatformIO monitor…).

Only one process can hold the port at a time. Close the setup page's serial session (or your terminal) before opening the other.

Commands are case-sensitive. Addresses are hex (24-bit), rolling codes and indices are decimal. Most commands answer OK, OK <idx>, an ERR … line, or a one-line JSON document.

Shade JSON (list / export)

One object per used slot, on a single line:

{"idx":0,"name":"Salon","addr":"0EB998","rolling":1498,"on":true,
 "remote":true,"link":"6FDA96","up_ms":35000,"down_ms":30000,
 "my":255,"invert":true,"up_lag":0,"down_lag":0,"pos":0}
FieldMeaning
idxSlot index — stable per shade, used by every mutating command.
nameDisplay name (≤15 chars).
addr24-bit Somfy address (hex) the shade transmits as.
rollingRolling-code counter. Must stay ahead of what the motor last accepted.
onExposed as a Matter WindowCovering endpoint over Thread.
remoteCloned from a physical remote (true) vs PROG-paired (false).
linkAddress of a monitored wall remote (000000 = none).
up_ms / down_msFull-open / full-close travel times (ms). 0 = snap to target.
myFavourite ("my") position 0–100. 255 = unset.
invertSwap open/close for reversed installs.
up_lag / down_lagStartup dead-time before the shade visibly moves (ms).
posCurrent lift estimate, 0–10000 (hundredths of a percent, 0 = open).

Expectations & gotchas

  • Rolling-code sync before transmitting. Somfy RTS is one-way and rejects a code the motor has already seen. If a motor is also driven by another controller/remote, roll the shade to that controller's current counter (or higher) before any tx, or the motor will ignore the frame.
  • Position is estimated, not measured. The motor never reports where it is. The firmware ramps pos from travel times (pos command). A full open/close re-zeros drift against the end stop.
  • "My" is context-dependent. While moving it acts as Stop; while idle it drives toward my_pct — set that to match the favourite you programmed on the motor.
  • NVS wipe on a merged flash. Flashing the merged image at offset 0 blanks the shade store (addresses, rolling codes, positions). Back up with export first, or flash app-only. Matter pairing credentials survive.
  • reset keeps shades but clears Matter. Endpoint ids are re-derived on the next boot, so the device re-commissions but your shades remain.
  • Endpoint ids are stable. on 0 hides a shade from Thread but keeps its id, so on 1 restores the same Matter identity.
